# Linux 无超线程 P 核计数修复验证

日期：2026-10-22。源码补丁及本地构建验证，未发布新版本。

## 修复范围

项目基线为 `5189a170ff30abcf534de42ac3579c5be2b84c35`，继续固定 llama.cpp
`86a283532072722c5f3363d37d59a874d09fa99b`。检查上游 `c7fc5094` 时，Linux x86 混合 CPU
路径仍以额外的 `++cpu` 跳过假定的超线程兄弟；相关上游 PR #21979 已关闭且未合并。

新增 `0004-fix-hybrid-cpu-core-count.patch`，由现有 CMake 补丁流程自动应用。
只修改 Linux x86_64、非 Android 的混合 CPU 自动线程探测：

- 按调用线程原始亲和性掩码逐个访问允许的 CPU，不假定 CPU 编号连续。
- 保留排除 E 核的策略，使用内核 `topology/thread_siblings` 内容去重物理 P 核。
- 无 SMT 时每个 P 核计一次；开启 SMT 时同一物理 P 核的兄弟线程合计一次。
- 绑核或拓扑读取失败时放弃部分计数，恢复原始亲和性后使用已有物理核心回退值，且不超过原始允许 CPU 数。
- 正常、失败及异常退出均通过亲和性守卫恢复；恢复系统调用失败时再尝试一次。

Windows、macOS、非混合 CPU 的现有路径及公开接口不变。显式线程设置优先。
这里选择的是线程数量，不会将推理工作线程永久绑定到 P 核。

## 本机验证结果

机器：Intel Core Ultra 5 225H，4P + 8E + 2LP-E，14 核 / 14 线程，无 SMT。
P 核为 CPU 0–3；原始允许 CPU 为 0–13。两个 wheel 均由同一 GCC 15.2、Release、
AVX2 CPU、OpenMP 和 Vulkan 配置构建，版本仍为 0.1.3。

| 检查 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 安装包公共库自动线程数 | 2 | 4 |
| 默认批处理线程数 | 2 | 4 |
| 打包的 llama-server 实际线程池 | 2 | 4 |
| 显式 4 / 8 / 12 及其批处理默认值 | 保留 | 保留 |
| 探测前后线程亲和性 | 一致 | 一致 |

修复后的真实 Python Engine 使用本地 Q8_0 主模型和 mmproj 初始化，原生日志确认线程池为 4。
完成一次 1 token 的最小生成功能检查后正常关闭。两个版本的 llama-server 均使用 CPU 加载真实主模型，
`/health` 返回成功，随后正常退出；未测量性能。

修复后公共库在受限亲和性下的结果：

| 允许 CPU | 自动线程 / 默认批处理线程 |
| --- | --- |
| 0–13 | 4 / 4 |
| 1 | 1 / 1 |
| 1、3 | 2 / 2 |
| 4、5（只有 E 核） | 2 / 2，使用受限回退 |

## 回归与构建检查

- 13 个原生拓扑用例通过，直接复用生产补丁内的计数辅助函数，覆盖无 SMT、相邻/非相邻 SMT 兄弟、
  稀疏 CPU 编号、受限亲和性、只有 E 核、绑核失败、读取失败、空拓扑、异常恢复和恢复重试。
- 拓扑用例已加入现有 wheel 测试命令；非 Linux 平台跳过该组测试。
- 原生绑定、UTF-8、后端选择、可选后端异常和发布策略回归：基线 114 passed / 46 skipped；
  候选加入计数用例后 127 passed / 46 skipped。跳过项为平台限定检查。
- 干净子模块首次构建自动应用全部四个补丁；重复 CMake 配置识别四个补丁均已应用。
- 两个 `cp310-abi3-linux_x86_64` wheel 构建和隔离安装成功。它们是本机验证产物，未作为 manylinux 发布包审计或发布。
- 新增 Python 测试通过 Ruff，补丁通过 `git diff --check`。

测试条件与限制：修复前包在纯 Python 原生绑定的无效模型路径用例中已出现段错误；
前后包的上述回归统一在测试进程内预加载系统 `libstdc++.so.6` 后运行。未修改用户配置或产品加载行为。
另一个“仅初始化后立即关闭”的候选探针停留在等待状态，已手动终止，不计为通过；
已有 `server_queue::start_loop()` 和 `terminate()` 的启动/退出竞争需要另行排查，本补丁未修改该路径。
最小生成后关闭的检查通过。本次未运行完整模型生命周期压力测试或跨平台真机测试。

按用户后续要求取消性能测量：首轮 OCR 基线尚未完成即停止，调度器及工作进程均已终止，
不报告耗时或性能结论。
